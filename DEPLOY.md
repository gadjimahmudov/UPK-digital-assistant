# Деплой: как выложить проект в интернет

Цель: чтобы жюри (и любой телефон, **без общей Wi-Fi сети**) могли открыть `https://<имя>.pythonanywhere.com`, отсканировать QR и пройти весь сценарий.
Выбран **PythonAnywhere**: подходит для Flask, SQLite и загрузки фото, диск не стирается при перезапуске. Альтернатива (Render и др.) описана внизу.

## 0. Решите до начала

| Вопрос | Рекомендация |
|---|---|
| Пароль демо-аккаунтов | **Смените.** `demo12345` написан в README, а на публичном сервере им сможет войти кто угодно. Придумайте свой и сообщите жюри отдельно (в презентации или в форме сдачи) |
| Секреты `JWT_SECRET`, `TRACKING_SECRET` | Сгенерируйте: `python -c "import secrets;print(secrets.token_hex(32))"` (два раза, два разных значения). **Не публикуйте их на GitHub** |
| Тестовые данные | После проверки очистите базу (шаг 8), чтобы у жюри не было мусорных заявок |

## 1. Загрузите актуальный код на GitHub
В репозитории должны лежать `app.py`, `index.html`, `wsgi.py`, `requirements.txt`, `knowledge_base.json`. Проверьте, что `wsgi.py` добавлен: `git add wsgi.py DEPLOY.md && git commit -m "deploy" && git push`.

## 2. Аккаунт
Зарегистрируйтесь на pythonanywhere.com, тариф **Beginner (бесплатный)**. Имя пользователя станет частью адреса: `https://ИМЯ.pythonanywhere.com`.

## 3. Код и окружение (вкладка Consoles → Bash)
```bash
git clone https://github.com/gadjimahmudov/UPK-digital-assistant.git
mkvirtualenv --python=/usr/bin/python3.13 upk     # версию возьмите из тех, что предлагает PythonAnywhere
cd UPK-digital-assistant
pip install -r requirements.txt
```
Запомните версию Python: в шаге 4 нужно выбрать **ту же**.

## 4. Веб-приложение (вкладка Web)
1. **Add a new web app** → Next → **Manual configuration** → выберите ту же версию Python → Next.
2. Раздел **Code**, поле **Source code**: `/home/ИМЯ/UPK-digital-assistant`
3. Раздел **Virtualenv**: впишите `upk` (подставится полный путь).

## 5. WSGI-файл
Там же, в разделе Code, откройте ссылку **WSGI configuration file**, **удалите всё содержимое** и вставьте (подставьте ИМЯ и свои значения):

```python
import os, sys

path = '/home/ИМЯ/UPK-digital-assistant'
if path not in sys.path:
    sys.path.insert(0, path)

os.environ['JWT_SECRET'] = 'ВСТАВЬТЕ_ПЕРВОЕ_СЛУЧАЙНОЕ_ЗНАЧЕНИЕ'
os.environ['TRACKING_SECRET'] = 'ВСТАВЬТЕ_ВТОРОЕ_СЛУЧАЙНОЕ_ЗНАЧЕНИЕ'
os.environ['DEMO_PASSWORD'] = 'ВАШ_ПАРОЛЬ_ДЛЯ_ДЕМО'

from wsgi import application
```
Этот файл лежит на сервере PythonAnywhere, а не в репозитории, поэтому секреты не попадут на GitHub. Нажмите **Save**.

> `DEMO_PASSWORD` действует только при **создании** базы. Если сервер уже запускался с другим паролем, в Bash выполните `rm ~/UPK-digital-assistant/upk.db`, затем Reload.

## 6. Запуск
На вкладке Web нажмите зелёную кнопку **Reload**. Откройте `https://ИМЯ.pythonanywhere.com`: должна открыться форма заявки. Если ошибка, смотрите **Error log** на вкладке Web (ссылка рядом с WSGI-файлом).

## 7. Проверка (с вашего компьютера, не с PythonAnywhere)
```bash
python smoke_test.py https://ИМЯ.pythonanywhere.com upk1 ВАШ_ПАРОЛЬ
```
Ожидается `✅ 20 ❌ 0`. Затем проверьте руками **с телефона на мобильном интернете** (не на Wi-Fi): откройте сайт, спросите ИИ «В розетке искрит», создайте заявку с фото, войдите как сотрудник, смените статус, откройте ссылку отслеживания.

Тест создаёт в базе пробную заявку: перед защитой очистите данные (шаг 8).

## 8. Очистка базы перед защитой
В консоли Bash PythonAnywhere:
```bash
cd ~/UPK-digital-assistant
rm -f upk.db && rm -rf storage
```
Затем **Reload**. База создастся заново (пустая, с демо-пользователями, категориями и местами).

## 9. Обновите QR-коды и README
```bash
pip install "qrcode[pil]"
python make_qr.py https://ИМЯ.pythonanywhere.com
```
Файлы появятся в папке `qr/`: замените ими `QR_*.png` в репозитории (или добавьте новые). Теперь QR работает с любого телефона из любой сети (HTTPS).

В README замените абзац про GitHub Pages на:
```markdown
## 🌐 Онлайн-демо
**https://ИМЯ.pythonanywhere.com** (откройте с телефона или отсканируйте `QR_*.png`).
Логин для проверки: `admin`, пароль сообщён жюри отдельно.
```
Если оставляете публичный пароль `demo12345`, так и напишите, но учтите, что любой сможет войти и менять заявки.

Обновление после правок: `git push` на GitHub, затем в Bash `cd ~/UPK-digital-assistant && git pull`, затем **Reload**.

## 10. Чек-лист перед защитой
- [ ] Сайт открывается по `https://` с телефона на мобильном интернете
- [ ] QR-код (распечатанный или на экране) ведёт на рабочую форму с выбранным местом
- [ ] «В розетке искрит» показывает красное предупреждение
- [ ] Заявка создаётся, ссылка отслеживания открывается
- [ ] Вход сотрудника работает, статусы меняются
- [ ] База очищена от тестовых заявок (шаг 8)
- [ ] Запасной план: 2-минутное видео демо и локальный запуск на ноутбуке (`python app.py`)
- [ ] Утром в день защиты откройте сайт и убедитесь, что он живой (бесплатные приложения требуют периодического продления: войдите в аккаунт PythonAnywhere и нажмите кнопку продления на вкладке Web, если она там есть)

## Ограничения публичной демо-версии
Нет защиты от массовой отправки заявок (ограничения частоты не реализованы), открытый CORS, общий демо-пароль. После защиты удалите веб-приложение или смените пароль.

## Альтернатива: Render (и похожие сервисы на gunicorn)
- Build command: `pip install -r requirements.txt gunicorn`
- Start command: `gunicorn wsgi:app`
- Переменные окружения: `JWT_SECRET`, `TRACKING_SECRET`, `DEMO_PASSWORD`.
- **Проверьте условия бесплатного тарифа на сайте сервиса:** на бесплатных тарифах диск обычно не сохраняется между перезапусками и деплоями, поэтому SQLite-база и фото могут пропасть, а приложение после простоя «засыпает» и первый запрос идёт долго. Для демонстрации на защите PythonAnywhere надёжнее.
