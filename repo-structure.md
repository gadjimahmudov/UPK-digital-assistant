# Структура репозитория (актуальная)

Проект плоский: всё лежит в корне, запускается одной командой `python app.py`.

```text
UPK-digital-assistant/
├── app.py                 # backend: Flask + SQLite, API, ИИ на правилах, раздача index.html на «/»
├── index.html             # интерфейс: заявитель, отслеживание, панель сотрудника (HTML+CSS+JS, один файл)
├── knowledge_base.json    # база знаний ИИ (11 статей); подхватывается при старте сервера
├── requirements.txt       # flask, pyjwt
├── make_qr.py             # генерация QR-кодов для мест (нужна qrcode[pil])
│
├── test_api.py            # автотесты API (7)
├── test_ai.py             # автотесты ИИ-модуля и главной страницы (7)
├── smoke_test.py          # проверка ЖИВОГО сервера по шагам (20 проверок)
├── test_cases.json        # 10 тестовых обращений из ТЗ для ИИ
│
├── README.md              # запуск, демо-сценарий, ИИ, ограничения
├── api-contract.md        # контракт API (с пометкой, что реализовано)
├── system_prompt.md       # ПРОЕКТ на будущее: промпт для LLM (в MVP не используется)
├── schema.sql, seed.sql   # целевая схема и данные для PostgreSQL (MVP на SQLite, схема в app.py)
├── QR_214.png, QR_305.png, QR_Lab.png   # QR-коды мест
└── UPK_Presentation.pdf / .pptx         # презентация
```

Создаются при работе (в `.gitignore`): `upk.db` (база), `storage/` (фото), `.secrets_*` (секреты, сгенерированные при первом запуске).

## Куда расти (если проект продолжится)
- Разделить `app.py` на модули (маршруты, ИИ, база) и перенести SQLite → PostgreSQL по `schema.sql`.
- Админ-интерфейс (локации, сотрудники, QR), ограничение частоты запросов, уведомления.
- Подключить языковую модель по `system_prompt.md`, оставив правила как предфильтр опасности и запасной режим.
