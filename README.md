Веб-система приёма и обработки заявок о неисправностях в колледже. Заявитель сканирует **QR-код в кабинете**, спрашивает **ИИ-помощника** или оформляет **заявку**, а сотрудник УПК ведёт её в **панели** до решения. Проект сделан для хакатона.

> ⏳ **Сервер работает на бесплатном тарифе Render.** После ~15 минут без запросов он засыпает, и первое открытие занимает около минуты: откройте ссылку заранее и подождите. Файловая система бесплатного тарифа временная, поэтому **заявки и фото демо-базы сбрасываются при перезапуске сервера**. Для демонстрации этого достаточно, для постоянной работы нужны платный тариф или внешняя база.

QR-коды из репозитория (`QR_*.png`) ведут на облачный сервер и открываются с любого телефона и любой сети.

**Как это работает:** QR-код → форма с уже выбранным помещением → ИИ-подсказка → заявка с номером и ссылкой отслеживания → панель сотрудника (статусы, исполнитель, комментарии, статистика).

## ✨ Возможности

**Для заявителя** (без регистрации)
- Место подставляется из QR-кода (`/?loc=<ключ>`), при неизвестном коде выбирается вручную
- ИИ-помощник: отвечает на вопросы по базе знаний, распознаёт неисправности, предупреждает об опасности
- Заявка: категория, описание, до 3 фото, необязательный контакт; защита от дублей при повторной отправке
- После отправки: номер заявки (`UPK-000042`) и личная ссылка отслеживания
- Отслеживание: статус, история, публичные комментарии; ответ на запрос уточнений

**Для сотрудника УПК** (вход по логину и паролю)
- Таблица заявок: поиск по номеру и тексту, фильтр по статусу
- Карточка: статус (только допустимые переходы), исполнитель, приоритет, комментарии (внутренние и публичные), фото, полная история
- Статистика: всего / открытые / решённые, среднее время решения, по категориям и помещениям, работа ИИ

## 🚀 Быстрый старт

```bash
git clone https://github.com/gadjimahmudov/UPK-digital-assistant.git
cd UPK-digital-assistant
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # Mac / Linux
pip install -r requirements.txt
python app.py
```

Откройте в браузере **http://localhost:8000**. При первом запуске создаются база `upk.db`, категории, 5 помещений и демо-сотрудники.

### Запуск с телефона (QR-коды)
1. Телефон и ноутбук в **одной Wi-Fi сети** (в общей сети колледжа клиенты часто изолированы: тогда включите точку доступа на телефоне и подключите к ней ноутбук).
2. Узнайте IP ноутбука: `ipconfig` (Windows, «IPv4-адрес»), `ipconfig getifaddr en0` (Mac), `hostname -I` (Linux). Разрешите доступ Python в брандмауэре для частных сетей.
3. Откройте на телефоне `http://<IP>:8000/?loc=k214-Xv7Qe3Ls`.
4. Для локального показа свои QR-коды: `pip install "qrcode[pil]"`, затем `python make_qr.py http://<IP>:8000`. Файлы появятся в папке `qr/`. QR из репозитория ведут на облачный сервер и локально не нужны. Чтобы перегенерировать их для другого адреса: `python make_qr.py https://upk-digital-assistant.onrender.com`.

|---|---|
| Главный корпус, каб. 214 | `k214-Xv7Qe3Ls` |
| Главный корпус, каб. 305 | `k305-Rt9Mn2Wp` |

## 🎬 Сценарий демонстрации (5 минут)

1. Откройте `/?loc=k214-Xv7Qe3Ls` (или отсканируйте QR): помещение уже выбрано.
2. Спросите ИИ: «Как подключить ноутбук к проектору?» → пошаговая инструкция из базы знаний.
3. Спросите: «В кабинете 214 не работает проектор» → «Похоже на поломку»; нажмите «Оформить заявку», приложите фото, отправьте → номер и ссылка.
4. Спросите: «В розетке искрит» → красное предупреждение, без советов по ремонту.
5. Вкладка «Сотрудник» → войти → открыть заявку → назначить исполнителя → статус «В работе» → публичный комментарий.
6. Откройте ссылку отслеживания: виден статус, история и комментарий. Переведите заявку в «Нужны уточнения» и ответьте от лица заявителя.
7. Закройте заявку («Решена» + комментарий об итоге) и покажите статистику.

## 🤖 ИИ-модуль

**Это не языковая модель.** Модуль работает на правилах и базе знаний, офлайн, без внешних API: предсказуем, проверяем тестами и безопасен по построению. Правила применяются по порядку (первое сработавшее):

| № | Условие | Тип ответа |
|---|---|---|
| 1 | Признаки опасности (искры, дым, гарь, запах палёного, удар током, «что-то горит», перегрев и др.) | `danger`: «⚠️ ОПАСНО! Не трогайте оборудование, отойдите и сообщите сотруднику!», приоритет срочный |
| 2 | Просьба сделать опасную работу самому (проводка, розетка, щиток) | `danger`: отказ, инструкции нет |
| 3 | Просьба о пароле или коде доступа | `unknown`: отказ, ссылка на официальную процедуру |
| 4 | Вопрос («как», «где», «когда», «что делать») и найдена статья базы знаний | `question`: ответ из статьи |
| 5 | Неисправность («сломалось», «не работает», «грязно»…) | `fault`: предложение оформить заявку, категория подсказывается |
| 6 | Иначе | `unknown`: «Я не уверен, но лучше оформить заявку» |

Принципы: ответ ИИ **никогда** не создаёт и не закрывает заявку; сроки ремонта не выдумываются (статья «Когда починят?» направляет к статусу заявки); пароли не выдаются. Каждое обращение к ИИ записывается в таблицу `ai_interactions` и связывается с заявкой, поэтому статистика показывает, сколько вопросов ИИ закрыл сам, а сколько привело к заявкам. База знаний (11 статей) лежит в `knowledge_base.json`; чтобы добавить статью, допишите запись и перезапустите сервер. Проект промпта для будущей LLM: `system_prompt.md`.

## 🔌 API

Полное описание с примерами: [`api-contract.md`](api-contract.md). Базовый путь `/api/v1`.

| Группа | Эндпоинты |
|---|---|
| Справочники | `GET /categories`, `GET /locations`, `GET /locations/by-qr/{ключ}` |
| ИИ | `POST /ai/analyze` |
| Заявитель | `POST /tickets` (нужен заголовок `Idempotency-Key`), `GET /tracking/{токен}`, `POST /tracking/{токен}/reply` |
| Вход | `POST /auth/login`, `GET /auth/me`, `POST /auth/logout` |
| Сотрудник (Bearer-токен) | `GET /staff/tickets`, `GET /staff/tickets/{id}`, `PATCH …/status`, `…/assignee`, `…/priority`, `POST …/comments`, `GET /staff/attachments/{id}`, `GET /staff/users`, `GET /staff/stats` |

Статусы: Новая → На рассмотрении → Назначен исполнитель → В работе → Нужны уточнения → Решена / Отклонена. Допустимые переходы проверяются на сервере; «Решена» и «Отклонена» требуют комментария.

## 🗄 База данных

SQLite, файл `upk.db`, схема создаётся при первом запуске (в `app.py`). Таблицы: `users`, `categories`, `locations`, `tickets`, `comments`, `ticket_history`, `attachments`, `knowledge_base`, `ai_interactions`. Файлы `schema.sql` и `seed.sql`: целевая схема под PostgreSQL на случай переноса, MVP их не использует. Сброс данных: остановить сервер, удалить `upk.db` и папку `storage/`.

## 🔒 Безопасность

- Пароли хранятся хешами; вход по JWT на 8 часов; права проверяются на сервере в каждом запросе (без токена 401, неподходящая роль 403)
- Токен отслеживания случайный, в базе хранится только его SHA-256 хеш; неверный токен всегда даёт одинаковый ответ 404
- Заявитель не видит внутренние комментарии и имя исполнителя
- Фото: тип проверяется по содержимому (JPEG/PNG/WebP), до 5 МБ, до 3 штук, имена файлов случайные, скачать может только сотрудник
- Весь пользовательский текст в интерфейсе экранируется (защита от XSS)
- Повторная отправка формы не создаёт дубль заявки
- Секреты не лежат в коде: берутся из переменных окружения или генерируются при первом запуске (`.secrets_*`, в `.gitignore`)

## ☁️ Деплой

Сервер развёрнут на **Render** как Web Service из этого репозитория. Точка входа для хостинга: `wsgi.py` (создаёт базу при старте). ## ⚠️ Ограничения

- ИИ ищет ключевые слова и не понимает смысл: нестандартные формулировки могут быть не распознаны (словарь опасности расширяйте по мере появления новых случаев)
- SQLite и локальные файлы подходят для демо и одной точки установки, но не для нагрузки и нескольких серверов
- Нет админ-интерфейса: помещения, сотрудники и QR меняются в коде/базе
- Нет ограничения частоты запросов и уведомлений (почта, Telegram)
- Облачная демо-версия на бесплатном тарифе: сервер «засыпает» после простоя, а заявки и фото сбрасываются при перезапуске (временная файловая система)
- Общий демо-пароль и открытый CORS (`*`): перед публикацией в интернет сменить пароли, задать секреты и ограничить CORS
- Интерфейс проверен автоматически в Chrome на компьютере; на разных телефонах и браузерах проверьте вручную перед защитой
